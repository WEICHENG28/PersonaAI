## 4. Demo 腳本（約 4.5 分鐘）

1. **開場**（30 秒）：痛點（缺少分享對象、交友尬聊、認識人很花時間），一句話介紹 PersonaAI。
2. **認識 AI 朋友**（60 秒）：阿澈先說明自己是 AI，分享想去看展的近況；用戶提到週末要去漫展；阿澈自然接話，「它記得的事」出現一筆新記憶。
3. **交辦任務**（40 秒）：對阿澈說「幫我找 3 個喜歡登山的人聊聊」→ 任務確認卡 → 打開開發者開關，工作日誌即時顯示：搜尋大廳、挑人、每一步的理由 → 分身開始代聊。
4. **模擬下次見面**（60 秒）：阿澈分享新近況，問「你上次說的漫展去了嗎？」，接著回報「你不在的時候我幫你聊了 6 個人，2 個跟你很合」→ 秀效率統計（附計算依據）和一筆不合適原因。
5. **本人接手**（40 秒）：打開雙向合適的對象 → 看接手重點 → 本人接手聊兩句。
6. **隱私與安心**（20 秒）：分身只知道可分享的資料；記憶可以刪除；AI 永遠標示。
7. **收尾**（20 秒）：回到工作日誌與效率統計總覽，再用一句話回到定位。

## 5. 風險與對策

| 風險 | 對策 |
|------|------|
| **P0 範圍太大，主線不穩** | 每 12 小時檢查進度；落後就依序把 F8、效率統計降為 P1；準備錄影備案 |
| 第一次聊天不足以準確建模 | 顯示置信度；之後每次見面持續補充；用戶可手動修正 |
| 推斷過度、記憶錯誤 | 記錄來源與置信度；提到一次只當線索；提供查看、修改、刪除 |
| 虛構故事被誤認為真實經歷 | 首次見面說明是 AI、故事虛構；不聲稱在現實中見過用戶 |
| 用戶對 AI 朋友產生情緒依賴 | 不用內疚、嫉妒、占有欲留人；明確 AI 邊界；留意負面回饋 |
| 主動聯繫造成打擾 | 用戶設定頻率，可暫停或關閉；沒回覆不責備 |
| AI 朋友和分身被搞混 | 不同頭像、不同對話框，介面清楚區分 |
| 分身模仿得不像本人 | 只模仿風格特徵；Demo 用調好的種子資料 |
| 分身編造用戶沒說過的經歷 | prompt 禁止；不知道的事回「這我要問本人」 |
| 本人接手後和分身說過的話矛盾 | 接手卡片列出「分身已替你說過的話」 |
| 言行異常提醒誤判 | 門檻設高；需累積訊息量；只提醒當事人 |
| LLM 延遲讓 Demo 卡頓 | 串流輸出；小任務用快速版模型；錄影備案 |
| 代聊被濫用、成本暴增 | 每日代聊次數上限 |
| 冷啟動 | 種子用戶 |

## 6. 決策紀錄

### 已決定
- [x] **參賽賽道：Agent**；以 Agent 評分標準為優先
- [x] 整合原版與 AI 朋友版：AI 朋友認識你，社交 Agent 替你找人
- [x] AI 朋友和分身分成兩個：AI 朋友不模仿任何人、有長期記憶、屬於用戶；分身只模仿說話風格、負責對外代聊
- [x] 建模事件由輕到重，不使用失戀等較重的事件
- [x] Big Five 只給 Agent 在後台用；MBTI、SBTI、性格報告給用戶當娛樂話題，不用於判定
- [x] 長期陪伴照 AI 朋友版規劃：近況、故事連續、模擬下次見面納入 MVP；關係成長、溝通練習、外語朋友放後續
- [x] 刪除 F14 Agent 自我調整：交友沒成不是 Agent 或用戶的問題，不據此調整 Agent
- [x] 工作日誌改成開發者開關，一般用戶預設看不到
- [x] 每位用戶只有一個 AI 朋友；多位 AI 朋友（原 F10 依興趣出現新 AI 朋友）移到後續功能
- [x] 開場告知 AI 身分與故事虛構
- [x] 分身 ↔ 分身代聊不需對方逐次同意（開啟社交 Agent 即同意）
- [x] 匹配通知分檔：單向合適 / 雙向合適；判定演算法待定；對方視角不顯示數字
- [x] 本人接手後不再交回分身
- [x] 歷史嘗試紀錄：記錄不合適原因、幫用戶了解自己、可重啟對話
- [x] 依評分標準新增功能：一句話交辦任務與完成條件、找人目的、工作日誌附理由、異常處理、判定 3 次取共識、MVP 判定簡單版、效率統計附計算依據（整理見 [05 評分導向功能補強](05_評分導向功能補強.md)）
