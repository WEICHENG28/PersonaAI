## 1. 參賽賽道：Agent

| 評分維度（各 25 分） | 評審看什麼 | PersonaAI 怎麼拿分 |
|---------------------|-----------|-------------------|
| 創意與創新性 | 任務設計、工作流程、互動方式 | 把「找到合得來的人」設計成 Agent 任務；一句話交辦任務、可設完成條件與找人目的；AI 朋友在聊天中認識你，分身替你出去聊；本人隨時接手的人機交接 |
| 作品完成度 | 任務執行、流程完整、運行穩定 | 主線從認識你、交辦任務、找人、代聊、判定、回報到接手，從頭到尾跑得通；異常處理（重試、稍後聊、多聊幾輪再判定）；判定 3 次取共識 |
| AI 技術應用 | 模型調用、任務規劃、自動化 | 5 個 Agent 分工；Agent 呼叫工具、自己規劃與決策；工作日誌（開發者開關）每一步都附理由；依任務選用不同模型 |
| 應用價值與潛力 | 任務效率提升、實際應用價值 | 效率統計附計算依據（代聊場數 × 人工平均時間）；找人目的可延伸到讀書、運動、興趣同好；隱私分層與產品原則，讓它像能上線的產品 |

## 2. 問題與機會

| 痛點 | 現況 | PersonaAI 的解法 |
|------|------|------------------|
| 缺少可以隨時分享日常的人；有朋友也怕一直打擾對方 | 只能找聊天機器人，但它只會等你問問題 | AI 朋友有自己的生活、會主動分享、記得你說過的事 |
| 交友軟體靠照片＋自介，看不出性格 | 滑卡片、配對後尬聊 | AI 朋友在聊天中認識你，用性格與對話契合度來找人 |
| 性格測驗太刻意、容易美化自己 | 用戶會挑「理想答案」 | 從你對 AI 朋友生活事件的自然反應觀察性格 |
| 認識新朋友很花時間，多數對話無疾而終 | 一個個聊、一個個放棄 | 社交 Agent 自動找人、分身先聊，合適才由本人接手 |
| 網路上的人「本人跟介紹不一樣」 | 只能自己聊久了才發現 | 對方言行和描述極度不一致時，AI 主動提醒 |
| 怕隱私外流 | 聊天內容可能被轉述 | 資料分層：記憶只給 AI 朋友，分身只拿你確認可分享的資料 |

## 3. 目標用戶

- **首要**：想認識「聊得來的人」但時間有限的大學生、年輕上班族；社交焦慮、不擅長開場的人。
- **次要**：希望下班後有人聊幾句、分享日常，但不一定有合適對象的人。
- 首版只開放成年人。

## 4. 競品與差異化

| 產品 | 做什麼 | PersonaAI 的不同 |
|------|--------|-----------------|
| Tinder / Bumble | 看照片配對 | 以性格與對話契合度找人，由 Agent 先篩 |
| 16Personalities | 問卷測 MBTI | 從聊天中的自然反應觀察，較難作假；MBTI 只當娛樂話題 |
| Character.ai / Replika | 和 AI 角色聊天、陪伴 | AI 朋友之外，還有社交 Agent 替你去認識真人，目的是連結現實關係 |

## 5. 給評審的亮點

**創意與創新性**
1. **AI 朋友 × 社交 Agent**：一個 AI 對內陪你、認識你，一個分身對外替你社交，分工明確。
2. **不像問卷的認識方式**：AI 朋友分享自己的生活事件，由輕到重，從你的自然反應觀察性格。
3. **一句話交辦任務**：「幫我找 3 個喜歡登山的人聊聊」，Agent 解析成任務、確認後執行，達到完成條件就停。

**AI 技術應用**
4. **看得到的 Agent**：打開開發者開關，工作日誌即時顯示 Agent 怎麼挑人、為什麼挑、何時決定通知你。
5. **多 Agent 協作**：AI 朋友、社交 Agent、分身、評審、隱私守門各司其職。

**作品完成度**
6. **完整閉環**：認識你 → 交辦任務 → 找人 → 代聊 → 判定 → AI 朋友回報 → 本人接手。
7. **穩定運作**：異常自動處理；判定 3 次取共識。

**應用價值與潛力**
8. **效率可量化**：「代聊 6 場 × 人工平均 20 分鐘 = 省下約 2 小時」，附計算依據。
9. **不只交友**：同一套流程可以找讀書夥伴、運動夥伴、興趣同好。
10. **失敗也有價值**：AI 朋友說明每次不合適的原因，幫你了解自己；不合適的對話也能重啟。
11. **可信任的設計**：AI 永遠標示、記憶可看可改可刪、單向／雙向合適可選、言行異常提醒。
