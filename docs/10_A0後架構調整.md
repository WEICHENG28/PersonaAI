## 1. 發生了什麼

A0 原本要建 Next.js 全端骨架，實際交付的是：

| | 07 原計畫 | A0 實際 |
|---|---|---|
| 前端 | Next.js 14 App Router | **Vite 6 ＋ React 19 SPA**（react-router、Zustand、Tailwind v4） |
| 後端 | Next.js API Routes ＋ worker | **沒有後端**：資料全由 `src/store/useDemoStore.ts` ＋ `src/demo/scenario.ts` 用腳本模擬 |
| 頁面 | 各線做自己的頁面 | **A 已做好全部頁面的 UI**（02 的 12 步都能點，但都是假資料） |
| 型別 | `lib/types.ts`（07 第 5 節） | 前端用 `src/lib/api/types.ts`（畫面用的型別，和 07 第 5 節不同） |
| token | `app/globals.css` | `src/theme/tokens.css`（Hum 主題） |
| 介面語言 | 繁體中文 | 簡體中文（zh-CN），多語已移除 |

**影響**：畫面幾乎都有了，這是好事；但 Agent 賽道要的「真的會規劃、呼叫 LLM、判定」的部分完全沒有後端可以放。SPA 跑在瀏覽器，**不能放 LLM 金鑰和 Supabase service role key**，所以一定要補一個後端。

## 2. 新架構（決定）

**保留 A 的 Vite 前端，另外加一個 Node 後端。** 不改回 Next.js（會丟掉 A 的成果）。

```text
瀏覽器（Vite SPA，src/）
  ├─ 模式 mock：照現在的 demo 腳本跑（零後端，當 Demo 備案）
  └─ 模式 http：fetch /api/* ──► 後端（server/，Node＋Hono，port 8787）
                                   ├─ 呼叫 LLM（金鑰只在這裡）
                                   └─ 讀寫 Supabase（service role）
                   worker（scripts/worker.ts）──► 推進社交 Agent 任務
瀏覽器也直接用 Supabase anon key：登入（Auth）、訂閱 Realtime
```

| 項目 | 選擇 |
|------|------|
| 前端 | 現有 Vite＋React 19 SPA；`VITE_API_MODE=mock｜http` 切換資料來源 |
| 後端 | `server/`：Node 20＋[Hono](https://hono.dev)＋zod，用 `tsx` 執行；Vite dev server 把 `/api` 代理到 `http://localhost:8787` |
| 資料庫／登入／即時 | 不變：Supabase（07 第 4 節 SQL 已在 `supabase/migrations/0001_init.sql`） |
| 登入流程 | 前端用 Supabase Auth 登入拿到 JWT → 呼叫 `/api/*` 時帶 `Authorization: Bearer <jwt>` → 後端驗證後取得 `users.id` |
| LLM | 不變：`openai` 套件接 OpenAI 相容 API，只在後端 |
| 測試 | vitest（前後端共用） |
| Demo | **本機**跑三個終端機：`npm run dev`（前端）、`npm run server`（後端）、`npm run worker`；部署到 Vercel 的只有前端（mock 模式，當備案） |

### 環境變數（`.env.local`，不可提交）

```bash
# 前端（Vite 只會把 VITE_ 開頭的給瀏覽器）
VITE_API_MODE=mock                # mock 或 http
VITE_SUPABASE_URL=
VITE_SUPABASE_ANON_KEY=
# 後端（只在 server/ 與 scripts/ 讀）
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
LLM_BASE_URL=
LLM_API_KEY=
MODEL_CHAT=
MODEL_REASON=
MODEL_FAST=
MODEL_EMBED=
EMBEDDING_DIM=1024
```
