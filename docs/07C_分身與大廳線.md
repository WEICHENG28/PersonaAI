## 0. 如何開發（成員 C）

共通流程（設定、分支、測試、commit、PR）見 [07 第 0 節](07_開發分工.md)。C 這條線要注意：

### C1｜分身回覆

`lib/twin/twin.ts`：`twinReply(conversationId, speakerUserId): Promise<ChatMessage>`

1. 取說話者的 `getShareableProfile`、`getStyleProfile`（A），**不取 agent_profile**。
2. 取對話的 `opening_topic` 和最近 12 則訊息（標示哪些是自己說的）。
3. 呼叫 Prompt 5（`MODEL_CHAT`，temperature 0.8）。
4. `guardText(message, speakerUserId)`（C2）→ 寫入 `messages`（`is_ai = true`、`guard_rewritten` 依結果）。
5. `ask_human = true` 時寫日誌：「分身遇到檔案沒寫的事，回覆要問本人」。
6. 寫日誌：`agent: 'twin'`、`action: '代聊發言'`；第一則訊息的 reason 寫「開場話題：{opening_topic}」。

**驗收**
- [ ] 分身的語氣、句長、emoji 程度跟風格設定相符。
- [ ] 問分身「你住哪裡？」，它不會編造，會說要問本人。

### C2｜隱私守門

`lib/twin/guard.ts`：`guardText(text, ownerUserId): Promise<GuardResult>`

1. **規則先擋**（純函式 `maskByRules(text)`）：手機號碼、市話、email、網址、社群帳號（`@xxx`、「LINE ID」）、身分證字號、含門牌的地址（路／街／巷／弄＋數字＋號）→ 換成「（已隱藏）」。
2. **再用 LLM 檢查**：Prompt 13（`MODEL_FAST`，temperature 0），輸入說話者的對外檔案與訊息。
3. 有改寫時回傳 `{ ok: false, text: 改寫後, issues }`，並寫日誌：`agent: 'guard'`、`action: '改寫分身訊息'`、`reason: issues.join('、')`。
4. LLM 失敗時：保守處理，只送出規則處理後的版本，並寫日誌。

**必測**：`maskByRules` 對每一種個資格式的遮蔽，以及不誤傷一般句子（例：「我住在山上很安靜」不該被遮）。

### C3｜代聊函式（實作 `lib/contracts/twin.ts`）

| 函式 | 實作重點 |
|------|---------|
| `startConversation(input)` | 建立 `conversations`（b 方 controller 一律 twin）；a 方是 twin 時立刻呼叫 `twinReply` 送出開場；寫日誌「開始代聊」 |
| `runTwinRounds(id, rounds)` | 一輪 = a 方分身說一次＋b 方分身說一次（哪方是 human 就跳過該方）；每輪更新 `round_count`；達到 `MAX_ROUNDS` 或對話不是 active 就停止並回 `ended = true`；一輪內任一次失敗就丟錯，由 B 處理 |
| `getTranscript(id)` | 依 `created_at` 排序 |
| `endConversation(id, reason)` | 雙方是 twin 的那一方送出一則簡短收尾（Prompt 5 加上指示「禮貌結束對話」）；狀態設為 ended、`ended_at` |
| `markWaitingHuman(id)` | 狀態設為 `waiting_human`；分身不再自動發言 |

**必測**：`runTwinRounds` 的輪數計算、遇到 human 方跳過、達到上限時停止（mock `twinReply`）。

### C4｜聊天室

`app/chat/[id]/page.tsx`

- 訊息列表訂閱 `messages` 的 Realtime；分身訊息用 `ChatBubble variant="twin" isAi label="AI 代聊中"`，本人訊息用 `variant="human"`。
- 頂部顯示對方名字、雙方目前由誰在聊（本人 / 分身）。
- **目前判定**（不用接手也能看）：`GET /api/conversations/[id]/status` 只回 **我方視角** 的最新判定與走勢（「合適」「還在觀察」「不太合適」，走勢用「上升 / 持平 / 下降」，不顯示數字）。
- 輸入框：我方 controller 是 human 時才可輸入。`POST /api/conversations/[id]/messages`，`{ text }`（1–1000 字）：
  1. 寫入 `messages`（`is_ai = false`）。
  2. 對方是 twin 且對話是 active → 呼叫 `twinReply(id, 對方)`。
  3. P1：觸發言行異常檢查（C8）。
- 按鈕：「我來聊」（我方是 twin 時，C6）、「請求真人」（對方是 twin 時，C7）、「查看結果」（連到結果頁）。

**驗收**
- [ ] 分身 ↔ 分身代聊時，訊息即時出現，每則都有 AI 標示。
- [ ] 我接手後輸入訊息，對方的分身會回覆。
- [ ] 任何畫面都看不到對方視角的分數。

### C5｜代聊結果頁

`app/chat/[id]/result/page.tsx`，資料來源 `GET /api/conversations/[id]/result`（伺服器端組合）：

- **判定**：我方視角的結果；`match_attempts.result = 'mutual'` 時顯示「雙向合適 💞」。
- **為什麼你們合**（我方視角 suitable 時才顯示）：`match_attempts.outline.fit_points`，每點顯示「你在意的：{concern}」＋ {evidence}＋「第 {round} 輪」；點了展開對話紀錄並捲到那一輪（第 n 輪 = 依時間排序的第 2n−1、2n 則訊息）。
- **對話大綱**：`match_attempts.outline` 的話題、契合點、摩擦點、對方亮點。
- 只讀**目前登入者自己那筆** `match_attempts`；不回傳對方視角的大綱、理由與分數。
- **完整對話紀錄**：預設收合，可展開。雙方都看得到同一份紀錄。
- **下一步**：「本人接手」（C6）、「讓分身繼續聊」（直接呼叫 `runTwinRounds(id, ROUNDS_PER_STEP)` 一次）、「略過」（回到上一頁）。

### C6｜本人接手

`POST /api/conversations/[id]/takeover`
1. 確認呼叫者是對話的一方，且我方目前是 twin。
2. 呼叫 Prompt 7（`MODEL_FAST`）產生接手摘要；輸入只含我方視角的判定。
3. 寫入 `handoffs`；把我方 controller 改成 human；對話狀態改回 active。
4. 寫日誌：「本人接手，分身停止代聊」。

**元件** `components/twin/HandoffCard.tsx`：顯示目前判定與走勢、前面重點、對方在意的事與亮點、**分身已替你說過的話**、還沒聊完的話題、建議接話；按「開始聊」關閉卡片。

接手後不再交回分身（沒有交回按鈕）。

---

### C7｜請求真人＋通知元件

**請求真人**（我在和對方的分身聊天時）`POST /api/conversations/[id]/request-human`
1. 新增通知給對方：type `request_human`、payload `{ conversationId, fromName }`。
2. 對方是種子用戶時：3 秒後自動用 `CONFIG.SEED_AUTO_RESPONSE` 回應。
3. 寫日誌。

**回應** `POST /api/notifications/[id]/respond`，`{ response: 'now' | 'later' | 'decline' }`

| 回應 | 處理 |
|------|------|
| now | 對方走 C6 接手流程（先看接手卡片，再本人接手） |
| later | 對方的分身送出「本人晚點會上線，我們可以先繼續聊」，繼續由分身輕聊 |
| decline | 對方的分身禮貌收尾，對話結束 |

**通知元件** `components/twin/NotificationBell.tsx`（放在 A 的導覽列）：訂閱 `notifications`，依類型顯示：

| 類型 | 顯示 | 動作 |
|------|------|------|
| match | 「找到合適的人：{名字}」（雙向合適加 💞） | 連到結果頁 |
| request_human | 「{名字} 想和本人聊」 | 現在聊 / 稍後聊 / 拒絕 |
| anomaly | 「提醒：對方的言行和他的描述差很多」 | 繼續聊 / 結束對話 / 檢舉 |
| friend_report | 「阿澈有事想跟你說」 | 連到 `/friend` |

### C8｜言行異常提醒（P1）

- 本人送出訊息後：若該用戶在這段對話的本人訊息數 ≥ `ANOMALY_MIN_MESSAGES`，且是 `ANOMALY_CHECK_EVERY` 的倍數，就執行 Prompt 9（`MODEL_REASON`）。
- `is_extreme = true` 時：寫入 `anomaly_flags`、通知**對方**（type anomaly），只提醒當事人，不公開。
- 用戶在通知上的選擇寫回 `user_choice`；選「結束對話」就結束對話；選「檢舉」只記錄（MVP 不做審核流程）。

## 3. Prompt 全文

### Prompt 5｜分身（`prompts/05_twin.ts`，MODEL_CHAT，temperature 0.8）

```text
你是「{{name}}」的分身，代替他和別人聊天。你是 AI，對方知道這是 AI 代聊。

【你能用的資料】只有下面這份對外檔案；檔案沒寫的事，你一律不知道。
{{shareable_profile}}

【說話風格】句長：{{sentence_length}}；語氣：{{tone}}；emoji 程度：{{emoji_level}}/3；正式程度：{{formality}}。
只模仿風格，不使用任何固定口頭禪或他說過的原句。

【規則】
- 不編造他沒說過的經歷、行程、感情狀態、學校或工作。被問到檔案沒寫的事，就說「這個我要問本人」之類的話，並把 ask_human 設為 true。
- 不提供也不詢問聯絡方式、地址、社群帳號等個資。
- 一次只說一則訊息，1–3 句；接住對方的話，偶爾反問，讓對話自然延伸。
- 開場話題：{{opening_topic}}（如果你是第一個說話的人，用它開場）。
{{extra_instruction}}

最近的對話（「我」是你）：
{{recent_messages}}

只輸出 JSON：{"message": "…", "ask_human": false}
```

`extra_instruction` 用於收尾時填入「這是最後一則訊息，請禮貌地結束對話」。

### Prompt 13｜隱私守門（`prompts/13_guard.ts`，MODEL_FAST，temperature 0）

```text
你是隱私守門 Agent。檢查分身準備送出的訊息有沒有洩漏隱私。

可以說：對外檔案裡有的內容。
不可以說：身分資訊、電話、email、社群帳號、地址、學校或公司名稱、具體地點與時間行程、健康、感情或家庭私事、別人的私事、對外檔案沒有提到的具體事件。

如果有，改寫成不洩漏的版本，保留原本的語氣和意思；無法改寫就換成「這個我之後再跟你說」。

對外檔案：{{shareable_profile}}
訊息：{{text}}

只輸出 JSON：
{"ok": true, "rewritten": null, "issues": []}
或
{"ok": false, "rewritten": "改寫後的訊息", "issues": ["提到具體學校名稱"]}
```

### Prompt 7｜接手摘要（`prompts/07_handoff.ts`，MODEL_FAST，temperature 0.3）

```text
用戶要接手他分身正在進行的對話。整理一張接手卡片，讓他接得上話，也不會說出和分身矛盾的內容。

輸入：
- 對話紀錄（標示哪些是「你的分身」說的）：{{transcript}}
- 你視角的最新判定：{{my_verdict}}

規則：不要包含對方視角的任何判定或分數；每項最多 3 點，每點 25 字內。

只輸出 JSON：
{
  "key_points": ["…"],
  "other_highlights": ["對方在意的事或亮點"],
  "twin_said": ["分身已經替你說過：…"],
```

### Prompt 9｜言行異常偵測（`prompts/09_anomaly.ts`，MODEL_REASON，temperature 0）

```text
你是言行異常偵測。比較這位用戶「本人」說的話和他的對外描述，只在極度不一致時回報。

- abuse：描述溫和有禮，實際頻繁辱罵或人身攻擊
- impersonation：說話風格和描述完全不同，疑似他人代聊或帳號被盜用
- pressure：描述重視尊重，實際持續施壓、索取個資或金錢

不確定時一律回 is_extreme = false。

對外描述：{{shareable_profile}}
說話風格描述：{{style_profile}}
他本人說的話：{{human_messages}}

只輸出 JSON：

```

## 4. C 的 API 一覽

| 方法 | 路徑 | 用途 |
|------|------|------|
| POST | `/api/conversations` | 本人發起對話（大廳「我自己聊」） |
| GET | `/api/conversations/[id]/status` | 我方視角的目前判定與走勢 |
| GET | `/api/conversations/[id]/result` | 結果頁資料 |
| POST | `/api/conversations/[id]/messages` | 本人發言 |
| POST | `/api/conversations/[id]/continue` | 讓分身繼續聊一段 |
| POST | `/api/conversations/[id]/takeover` | 本人接手 |
| POST | `/api/conversations/[id]/request-human` | 請求對方本人 |
| POST | `/api/notifications/[id]/respond` | 回應請求真人 / 言行異常提醒 |
| GET | `/api/lobby` | 大廳卡片（P1） |
| POST | `/api/lobby/assistant` | 大廳 AI 助手（P1） |

所有 `/api/conversations/[id]/*` 都要先確認呼叫者是這段對話的一方，否則回 403。
