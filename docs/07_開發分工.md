## 0. 如何開發

### 0.1 開工前要讀

| 你是 | 開工前要讀 |
|------|-----------|
| 成員 A 或開發 A 的 Agent | 本文件全部 → [07A](07A_AI朋友線.md) → 02 的 F1、F2、F7、F11、第 7 節 |
| 成員 B 或開發 B 的 Agent | 本文件全部 → [07B](07B_社交Agent線.md) → 02 的第 4 節、F4、F6、F8、F12、F13、第 6 節 |
| 成員 C 或開發 C 的 Agent | 本文件全部 → [07C](07C_分身與大廳線.md) → 02 的 F3、F4、F5、F7、F9、第 7 節 |

產品邏輯以 [02](02_核心邏輯與功能.md) 為準；這份文件定的是怎麼做：技術棧、資料夾、資料表、型別、跨線函式和時程。

### 0.2 第一次設定（每人做一次）

1. 安裝 Node.js 20 以上、Git，以及你要用的編輯器與開發 Agent（例如 VS Code＋Claude Code）。
2. **共用一個雲端 Supabase 專案**：由成員 A 建立，邀請另外兩人加入。使用規則見 0.8。
3. 三人先 `git clone https://github.com/WEICHENG28/PersonaAI.git`。成員 A 完成 A0（建立專案骨架）後**開 PR 合併到 main**（不可直接 push main），另外兩人再 `git pull`。
   - 專案骨架建在 **repo 根目錄**（不是 `personaai/` 子資料夾）。repo 已經有文件，`create-next-app` 先在別的空資料夾產生，再把檔案複製進來；`.gitignore` 要合併，不要覆蓋。
4. `npm install`（A0 已經把第 2 節列出的套件全部裝好，之後要新增套件先告訴 A，見 0.5）
5. `cp .env.example .env.local`，填入 Supabase 與 LLM 金鑰。金鑰私下傳給隊友，不要貼在群組，也不要 commit。
6. 資料庫：成員 A 在 M1 時於 Supabase 的 SQL Editor 執行 `supabase/migrations/0001_init.sql`，其他人不用重做。
7. 種子用戶：成員 C 完成 C0 後執行一次 `npm run seed`。
8. 開兩個終端機分別執行 `npm run dev` 和 `npm run worker`，打開 `http://localhost:3000`。

### 0.3 每個任務的開發流程

1. 從最新的 main 開分支：`git checkout -b b/B3-runner`（格式：`線別/任務ID-簡述`）。一個任務一條分支；同時讓多個 Agent 做不同任務時，每個 Agent 用自己的 `git worktree` 資料夾（見 [CONTRIBUTING.md](../CONTRIBUTING.md) 第 5 節）。
2. 把任務交給開發 Agent（指令範本見 0.4）。
3. **先寫測試**（各線文件列出的「必測」函式）→ 再實作 → `npm test` 全部通過。
4. 打開網站，照任務的「驗收」逐條確認。
5. 在 `docs/DEVLOG.md` 自己那條線的區塊最上面寫一筆紀錄，然後 Commit：`feat: B3 Agent 迴圈與 worker`（格式 `<type>: <描述>`，type 用 feat、fix、refactor、test、docs、chore）。
6. 先 `git pull origin main` 合入最新版、再跑一次 `npm test`，然後 push 並開 PR：
   - **只改自己那條線的檔案** → `npm test` 通過、網站能跑，就由自己合併。
   - **動到共用檔（0.5）或別條線的檔案** → 請相關的人看過再合併。
7. 合併後在群組通知，其他人 `git pull`。任務做太久時，每 1～2 小時先合併一個能跑的段落，不要累積到最後。

### 0.4 交給開發 Agent 的指令範本

把 `{ }` 換成你的線別和任務：

```text
你是 PersonaAI 的開發者，負責成員 {B} 的 {社交 Agent 線}。
1. 先讀 AGENTS.md、docs/07_開發分工.md 全部、{docs/07B_社交Agent線.md}，以及 docs/02_核心邏輯與功能.md 中 07 第 0.1 節列給這條線的章節。分支用 {b/B3-runner}。
2. 這次只做任務 {B3}，照 {07B} 裡這個任務的做法實作；只改屬於這條線的檔案（見 07 第 3 節）。
3. 需要別條線的功能時，只呼叫 lib/contracts/ 裡的函式；對方還沒做好就用 stub。
4. 先寫這個任務的「必測」測試，再實作，最後執行 npm test。
5. 完成後逐條回報「驗收」是否通過。
6. 如果需要修改共用檔（lib/types.ts、lib/contracts/ 的函式簽名、supabase/migrations/），或文件沒寫清楚，先停下來問我，不要自己決定。
```

### 0.5 共用檔怎麼改

共用檔：`lib/types.ts`、`lib/contracts/*.ts` 的函式簽名、`supabase/migrations/`、`package.json` 與 `package-lock.json`、`.env.example`、`app/globals.css` 的 token、`AGENTS.md`、`CONTRIBUTING.md`、`docs/` 的規格文件。

1. 在群組提出要改什麼、為什麼。
2. 三人同意後，由提出的人修改；資料表變更一律新增 migration 檔（例如 `0002_add_xxx.sql`），不改舊檔。**新增前先在群組喊編號**，避免兩人同時建出同號的 migration。
   - 要新增套件：告訴 A，由 A 在一個小 PR 裡安裝並合併，其他人 pull 後再 `npm install`。`package-lock.json` 衝突時不要手動合併，以 main 的版本為準重新 `npm install`。
3. 同步更新本文件對應的章節（第 4、5、6 節）。
4. 合併後通知另外兩人 pull，並在 Supabase 執行新的 migration。

### 0.6 里程碑整合

每到一個里程碑（第 9 節的 M1–M5），三人一起：
1. 把各自的分支合併到 main，`git pull`。
2. 執行 `npm test`。
3. 照第 10 節「主線驗收」跑到目前能跑的步驟。
4. 記下問題並分給負責的人。

### 0.7 卡住時

| 狀況 | 做法 |
|------|------|
| 別條線還沒做好 | 繼續用 stub 開發；在群組說明需要哪個函式、什麼時候要用 |
| LLM 輸出不穩定 | 先改 Prompt 的規則與範例，再降低 temperature；仍不穩就在程式端加規則檢查 |
| 文件沒寫到的產品邏輯 | 三人討論後補進 02，再繼續開發 |
| 進度落後 | 照 [03](03_分工進度與優先級.md) 的範圍提醒，先把 P1 留到最後 |

### 0.8 共用雲端資料庫注意事項

三人連的是**同一個** Supabase 專案，一個人的操作會直接影響另外兩人。

| 操作 | 規則 |
|------|------|
| 執行 migration、在 SQL Editor 改資料表 | 只照 0.5 的流程做，執行前後都在群組說 |
| `npm run db:reset`、清空資料表 | **會清掉所有人的資料**。只在三人同意時（例如 Demo 前）由一個人執行 |
| `npm run seed` | 只由 C 執行；要重跑先在群組說 |
| `npm run worker` | 每個人開的 worker 都會撈同一張 `agent_tasks`，同時開會搶同一個任務。**同一時間只開一個 worker**，開之前在群組說，用完關掉。B3 可以考慮加一個只處理指定用戶任務的開關，就能各自開發 |
| 開發 Agent | **不可**自行執行 SQL、migration、`db:reset`、`seed`，要用時先停下來問人 |

測試帳號用自己的名字開頭（例如 `a-test1@…`），方便分辨是誰建的資料。

## 2. 技術棧與環境

採用 [04 技術架構](04_技術架構.md) 的建議方案。要改動須三人同意，並同步修改本節。

| 項目 | 選擇 |
|------|------|
| 框架 | Next.js 14（App Router）＋ TypeScript（strict） |
| 樣式 | Tailwind CSS，顏色與字型用 CSS 變數（見第 8 節） |
| 資料庫 / 登入 / 即時 | Supabase：Postgres、Auth（Email＋密碼）、Realtime、pgvector |
| 資料驗證 | zod（所有 LLM 輸出、所有 API 輸入都要驗證） |
| LLM | `openai` npm 套件，接任何 OpenAI 相容的 API（用 `LLM_BASE_URL` 切換平台） |
| Agent 執行 | `scripts/worker.ts` 背景迴圈（`tsx` 執行），避免 Serverless 逾時 |
| 測試 | vitest（純邏輯單元測試，LLM 一律 mock） |
| 套件管理 | npm |

### 環境變數（`.env.local`，不可提交到 git）

```bash
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=        # 只在伺服器端與 worker 使用
LLM_BASE_URL=                     # OpenAI 相容端點
LLM_API_KEY=
MODEL_CHAT=Qwen3.8-Max            # AI 朋友、分身、回報、大廳助手
MODEL_REASON=DeepSeek-V4-Pro-0813 # 規劃、評審、檔案擷取、任務解析、異常偵測
MODEL_FAST=Qwen3.8-Flash          # 隱私守門、記憶擷取、接手摘要、卡片、娛樂標籤
MODEL_EMBED=GLM-Embedding-3
EMBEDDING_DIM=1024                # 要和資料表 vector(1024) 一致
```

`.env.example` 放同樣的欄位但不填值。啟動時檢查必要變數，缺少就直接報錯並說明缺哪一個。

### 指令

| 指令 | 用途 |
|------|------|
| `npm run dev` | 啟動網站 |
| `npm run worker` | 啟動 Agent 背景迴圈（社交 Agent 任務靠它推進） |
| `npm run seed` | 建立 10 位種子用戶（含檔案與向量） |
| `npm run db:reset` | 重設資料庫並套用 migration（Demo 前用） |
| `npm test` | 跑 vitest |

**Demo 以本機執行為主**：`npm run dev` ＋ `npm run worker` 同時開著。

## 4. 資料庫（`supabase/migrations/0001_init.sql`）

```sql
create extension if not exists vector;
create extension if not exists pgcrypto;

-- ===== 用戶與設定（A 建立，B、C 讀取）=====
create table users (
  id uuid primary key default gen_random_uuid(),
  auth_id uuid unique references auth.users(id) on delete cascade,  -- 種子用戶為 null
  display_name text not null,
  avatar_url text,
  is_seed boolean not null default false,
  social_agent_enabled boolean not null default false,
  match_tier text not null default 'mutual' check (match_tier in ('one_way','mutual')),
  purposes text[] not null default '{friend}',
  preferences jsonb not null default '{"personality":"similar","conditions":[]}'::jsonb,
  daily_chat_limit int not null default 10,
  manual_minutes_per_chat int not null default 20,
  proactive_frequency text not null default 'normal' check (proactive_frequency in ('off','low','normal')),
  dev_mode boolean not null default false,
  created_at timestamptz not null default now()
);

-- ===== AI 朋友（A）=====
create table ai_friends (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null unique references users(id) on delete cascade,
  persona_key text not null default 'ache',
  story_stage int not null default 0,
  life_state jsonb not null default '{}'::jsonb,
  shared_event_ids text[] not null default '{}',
  intro_done boolean not null default false,
  created_at timestamptz not null default now()
);

create table friend_messages (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references users(id) on delete cascade,
  role text not null check (role in ('user','friend')),
  kind text not null default 'chat' check (kind in ('chat','intro','life_update','report','task_card')),
  content text not null,
  meta jsonb not null default '{}'::jsonb,
  created_at timestamptz not null default now()
);

create table user_memory (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references users(id) on delete cascade,
  content text not null,
  source text not null default 'user_stated',
  confidence real not null check (confidence between 0 and 1),
  created_at timestamptz not null default now(),
  deleted_at timestamptz
);

create table user_profiles (
  user_id uuid primary key references users(id) on delete cascade,
  shareable_profile jsonb,                       -- ShareableProfile
  shareable_confirmed boolean not null default false,
  agent_profile jsonb,                           -- AgentProfile（Big Five 只給 B 用）
  fun_labels jsonb,                              -- 僅供娛樂
  card jsonb,                                    -- C 產生的大廳卡片快取
  embedding vector(1024),                        -- shareable_profile 的向量
  updated_at timestamptz not null default now()
);

-- ===== 社交 Agent（B）=====
create table agent_tasks (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references users(id) on delete cascade,
  kind text not null default 'search' check (kind in ('search','single')),
  raw_instruction text,
  restatement text,                              -- 給用戶確認的複述
  purpose text not null default 'friend',
  conditions jsonb not null default '[]'::jsonb,
  target_count int not null default 3,
  done_condition jsonb not null default '{}'::jsonb,
  target_user_id uuid references users(id),      -- kind = single 時使用
  status text not null default 'pending_confirm'
    check (status in ('pending_confirm','running','done','paused','failed','cancelled')),
  progress jsonb not null default '{"screened":0,"chats":0,"suitable":0}'::jsonb,
  active_conversation_id uuid,
  attempted_user_ids uuid[] not null default '{}',
  fail_count int not null default 0,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

-- ===== 對話（C）=====
create table conversations (
  id uuid primary key default gen_random_uuid(),
  side_a uuid not null references users(id),     -- 發起方
  side_b uuid not null references users(id),
  side_a_controller text not null check (side_a_controller in ('human','twin')),
  side_b_controller text not null check (side_b_controller in ('human','twin')),
  status text not null default 'active' check (status in ('active','waiting_human','ended')),
  origin text not null check (origin in ('auto','manual')),
  task_id uuid references agent_tasks(id),
  opening_topic text,
  round_count int not null default 0,
  created_at timestamptz not null default now(),
  ended_at timestamptz
);

create table messages (
  id uuid primary key default gen_random_uuid(),
  conversation_id uuid not null references conversations(id) on delete cascade,
  sender_id uuid not null references users(id),
  is_ai boolean not null,
  guard_rewritten boolean not null default false,
  content text not null,
  created_at timestamptz not null default now()
);

create table handoffs (
  id uuid primary key default gen_random_uuid(),
  conversation_id uuid not null references conversations(id) on delete cascade,
  user_id uuid not null references users(id),
  summary jsonb not null,
  created_at timestamptz not null default now()
);

-- ===== 判定與歷史（B）=====
create table match_scores (
  id uuid primary key default gen_random_uuid(),
  conversation_id uuid not null references conversations(id) on delete cascade,
  perspective_user_id uuid not null references users(id),
  round int not null,
  runs jsonb not null,                            -- 3 次判定的原始結果
  direction_score int not null,
  verdict text not null check (verdict in ('suitable','unsuitable','uncertain')),
  reason_type text,
  reason_text text,
  created_at timestamptz not null default now()
```

## 7. 給開發 Agent 的共通規則

1. **AI 永遠標示**：所有 AI 產生的訊息（AI 朋友、分身）在畫面上都要有 `<AiBadge/>`；分身訊息另外標示「AI 代聊中」。
2. **AI 朋友和分身外觀要不同**：不同頭像、不同對話框顏色（用第 8 節的 token）。
3. **隱私分層**：分身只拿 `getShareableProfile` 和 `getStyleProfile`；Big Five 只有 B 的後台邏輯能用；前端永遠不顯示對方視角的分數，也不顯示對方視角的大綱與合適理由（最多顯示「對方也覺得合適 💞」）。
4. **每個 Agent 動作都寫日誌**：呼叫 `writeLog`，`reason` 用一句話說明為什麼。
5. **所有 LLM 呼叫都走 `lib/llm`**，輸出用 zod schema 驗證；不在元件或 route 裡直接 new OpenAI client。
6. **所有 API 輸入都用 zod 驗證**；錯誤回傳 `{ ok: false, error: '給用戶看的中文訊息' }`，成功回傳 `{ ok: true, data }`；伺服器端記錄完整錯誤。
7. **只在伺服器端用 service role key**；前端只用 anon key 讀自己的資料與訂閱 Realtime。
8. **不可變更新**：更新物件時建立新物件，不直接修改傳入的參數。
9. **介面文字用繁體中文**；程式碼、變數、檔名用英文。
10. **純邏輯寫測試**：各線文件列出的「必測函式」都要有 vitest 測試；LLM 一律 mock。
11. **檔案大小**：單一檔案不超過 400 行，函式不超過 50 行。

## 10. 主線驗收（整合測試）

照 [03 的 Demo 腳本](03_分工進度與優先級.md) 跑一次，每一步都要符合：

| # | 操作 | 預期結果 | 負責 |
|---|------|---------|------|
| 1 | 新用戶註冊並登入 | 自動建立 `users`、`ai_friends`、`user_profiles`；進入 AI 朋友聊天頁 | A |
| 2 | 第一次打開聊天頁 | 阿澈先說明自己是 AI、故事是虛構的，接著分享一個輕事件 | A |
| 3 | 用戶說「我週末要去漫展」 | 阿澈自然接話；「它記得的事」出現一筆記憶 | A |
| 4 | 聊滿 6 則後到「我的對外檔案」 | 看得到檔案草稿，確認後可以開啟社交 Agent；看不到 Big Five | A |
| 5 | 對阿澈說「幫我找 3 個喜歡登山的人聊聊」 | 出現任務確認卡，複述目的、條件、完成條件 | A → B |
| 6 | 按確認，打開開發者開關 | 工作日誌即時出現：搜尋大廳、選人與理由、開始代聊 | B |
| 7 | 等 worker 跑 | 分身 ↔ 分身對話即時出現在聊天室，每則都標示 AI 代聊中；有隱私改寫時日誌有紀錄 | C |
